## Executive Summary

Ralph Loop Manager is a web-based platform for managing, monitoring, and orchestrating **Ralph loops** - AI-driven development workflows that execute continuously in isolated Docker containers. The platform provides complete lifecycle management for AI-powered iterative development, with real-time monitoring, task management, and integration with multiple LLM providers.

### Current Implementation Status: 65% Complete

**What's Working (✓):**
- Complete Rust workspace architecture (5 crates)
- Type-safe SQLite database with migrations and optimizations
- Full authentication system (registration, login, sessions, CSRF, rate limiting)
- Loop management (CRUD, ownership, status transitions)
- Task management (CRUD, hierarchical tasks, priority ordering)
- Docker containerization with resource limits and lifecycle management
- Multi-LLM provider support (Claude, OpenAI, Mock for testing)
- Real-time WebSocket updates for loop progress
- Complete HTTP API with comprehensive middleware stack
- Basic HTML templates with HTMX and Tailwind CSS

**What's Missing (✗):**
- Git integration (no GitService, unused git fields)
- API key management (no tables, repositories, handlers)
- OAuth authentication (no flow, token storage)
- Advanced task features (no drag & drop, Kanban, import/export)
- Advanced loop features (no auto-commit, templates, sharing)
- Enhanced templates (minimal template coverage)

**Business Impact of Gaps:**
- **Git Integration (Critical):** Without automated Git operations, developers must manually push code and manage branches, defeating the purpose of an AI development workflow
- **API Keys (High Priority):** Users cannot manage multiple API keys or rotate credentials, creating security and operational issues
- **OAuth (LowPriority):** Lack of social login limits user adoption and increases friction
- **Advanced Task Features (Low Priority):** Without enhanced UX, task management remains basic and less efficient

## 1. Product Overview

### 1.1 Problem Statement

Modern AI-driven development workflows (like "Ralph" technique: `while :; do cat PROMPT.md | npx amp; done`) face several challenges:

1. **Execution Isolation:** AI code generation and execution requires secure isolation to prevent system compromise
2. **State Management:** Managing PRDs, tasks, iterations, and generated files across multiple sessions is complex
3. **Monitoring:** Real-time progress tracking of long-running AI loops is difficult
4. **Task Orchestration:** Prioritizing, creating, and managing hierarchical tasks generated by LLMs requires automation
5. **Integration:** Connecting AI outputs to version control systems (Git) is manual and error-prone
6. **Resource Control:** AI processes can consume unbounded CPU/memory without proper limits

### 1.2 Solution Overview

Ralph Loop Manager provides a complete web platform for managing AI-driven development loops:

- **Web Interface:** Intuitive dashboard for creating and managing Ralph loops
- **Docker Isolation:** All loops execute in isolated containers with resource limits
- **Real-time Monitoring:** WebSocket streaming of loop progress and task completion
- **Task Management:** Hierarchical task creation (manual + AI-generated) with priority ordering
- **Multi-LLM Support:** Integration with Claude, OpenAI, and extensible provider architecture
- **Database Persistence:** Complete history of loops, tasks, iterations, and generated files
- **Security:** Authentication, CSRF protection, rate limiting, session management
- **API Access:** RESTful API for programmatic control

### 1.3 Target Users

**Primary Users:**
- **AI-Powered Developers:** Using LLMs to accelerate development workflows
- **DevOps Engineers:** Automating repetitive coding tasks with AI
- **Technical Leads:** Orchestrating AI agents for team projects

**Secondary Users:**
- **Researchers:** Using AI for rapid prototyping and experimentation
- **Startup Founders:** Building MVPs with AI assistance

### 2.8 Loop Execution

**Status:** ✓ COMPLETE (100%)

**Implementation:**
- **LoopExecutor** service orchestrates Ralph loop execution:
  - Task queue processing (priority-based)
  - LLM interaction via CodeAgent
  - Command execution via ExecutionContext
  - State transitions (Created → Running → Paused → Completed/Error)
  - Iteration counter management
  - Max iterations enforcement
  - Auto-creation of tasks from LLM suggestions
- Background task spawning for async execution
- Error handling with logging (doesn't stop loop on task failure)

**Execution Flow:**
```
1. User clicks "Start Loop"
2. LoopExecutor.start() creates Docker container
3. LoopExecutor spawns background execution_loop task
4. Loop: while running and tasks exist:
   a. Find next pending task (highest priority)
   b. Update task status to InProgress
   c. Execute task via CodeAgent
   d. Process LLM suggestions (create new tasks)
   e. Update task status to Completed/Failed
   f. Increment iteration counter
   g. Sleep iteration_delay
5. Loop completes when: no tasks OR max_iterations reached OR stopped by user
6. Container stopped and removed
7. Loop status updated to Completed/Error
```

**API:** Loop control endpoints (`/start`, `/pause`, `/resume`, `/stop`)

## 4. Requirements for Missing Features

### 4.1 Git Integration Requirements

**Feature Name:** Automated Git Operations

**User Stories:**
- As a developer, I want loops to automatically commit generated code to Git, so I don't have to switch between the app and Git CLI
- As a developer, I want loops to create PRs/MRs on completion, so I can review and merge AI-generated code
- As a developer, I want to use my Git credentials without committing them to the codebase, so they remain secure

**Functional Requirements:**

**4.1.1 GitService Specification**
```rust
// ralph-services/src/git.rs
use anyhow::Result;
use std::path::Path;

pub struct GitService {
    repo_path: PathBuf,
    credentials: GitCredentials,
```

```rust
// ralph-services/src/crypto.rs
use anyhow::Result;
use aes_gcm::Aes256Gcm;
use aead::{Aead, KeyInit};

const ENCRYPTION_KEY: &[u8; 32] = &/* from environment */;

pub fn encrypt_api_key(plaintext: &str) -> Result<String> {
    let cipher = Aes256Gcm::new(ENCRYPTION_KEY);
    let nonce = Aes256Gcm::generate_nonce(&cipher);
    let ciphertext = cipher.encrypt(&nonce, plaintext.as_bytes())
        .map_err(|e| anyhow!("Encryption failed: {}", e))?;

    // Store nonce + ciphertext
    let mut combined = nonce.to_vec();
    combined.extend(ciphertext);
    Ok(base64::encode(&combined))
}

pub fn decrypt_api_key(ciphertext: &str) -> Result<String> {
    let combined = base64::decode(ciphertext)?;
    let (nonce, ciphertext) = combined.split_at(12); // nonce is 12 bytes
    let cipher = Aes256Gcm::new(ENCRYPTION_KEY);
    let plaintext = cipher.decrypt(&nonce, ciphertext.as_ref())
        .map_err(|e| anyhow!("Decryption failed: {}", e))?;
    Ok(String::from_utf8(plaintext)?)
}
```

```rust
        sqlx::query!(

            INSERT INTO api_keys (id, user_id, provider, encrypted_key, is_active, created_at, updated_at)
            VALUES ($1, $2, $3, $4, $5, $6, $7)
            "#,

            create.user_id,
            create.provider,
            encrypted,
            true,
            chrono::Utc::now().to_rfc3339(),
            chrono::Utc::now().to_rfc3339()
        )
        .execute(&self.pool)
        .await?;

        Ok(create.into_api_key())
    }

    pub async fn list_by_user(&self, user_id: &str, provider: ApiKeyProvider)
        -> Result<Vec<ApiKey>> {
        let rows = sqlx::query_as!(
            ApiKeyRow,
            r#"SELECT id, user_id, provider, encrypted_key, is_active, created_at, updated_at
               FROM api_keys
               WHERE user_id = $1 AND provider = $2
               ORDER BY created_at DESC"#,
            user_id,
            provider
        )
        .fetch_all(&self.pool)
        .await?;

                    id: row.id,
                    user_id: row.user_id,
```

```rust
// ralph-server/src/handlers/oauth.rs
pub async fn oauth_authorize(
    State(oauth): State<Arc<OAuthService>>,
    State(csrf): State<Arc<CsrfManager>>,
    Query(params): Query<OAuthAuthorizeParams>,
) -> Result<Redirect> {
    let state = csrf.generate_state();
    let auth_url = oauth.get_authorization_url(&params.provider, &state);

    // Store state in session for verification
    session.set("oauth_state", &state)?;
    session.set("oauth_provider", &params.provider)?;

    Ok(Redirect::to(&auth_url))
}

pub async fn oauth_callback(
    State(oauth): State<Arc<OAuthService>>,
    State(repo): State<Arc<UserRepository>>,
    State(token_repo): State<Arc<OAuthTokenRepository>>,
    State(csrf): State<Arc<CsrfManager>>,
    Query(params): Query<OAuthCallbackParams>,
    Session(session): SessionExtractor,
) -> Result<Html<String>> {
    // Verify state matches
    let stored_state = session.get("oauth_state")?;
    if stored_state != params.state {
        return Err(anyhow!("Invalid OAuth state"));
    }

    // Exchange code for token
    let token = oauth.exchange_code(&params.provider, &params.code).await?;

    // Get user profile
    let profile = oauth.get_profile(&params.provider, &token.access_token).await?;

    // Find or create user
    let user = match repo.find_by_oauth_id(&params.provider, &profile.id).await? {
        Some(u) => u,
        None => repo.create_from_oauth(profile).await?,
    };

    // Store OAuth token
    token_repo.create(user.id.clone(), params.provider.clone(), token).await?;

    // Create session
    session.set("user_id", &user.id)?;

    // Redirect to dashboard
    Ok(redirect("/loops"))
}
```

```rust
// ralph-server/src/handlers/tasks.rs
use csv::Writer;

pub async fn export_tasks(
    State(repo): State<Arc<TaskRepository>>,
    Auth(user_id): AuthExtractor,
    Path(loop_id): Path<String>,
) -> Result<impl IntoResponse> {
    let tasks = repo.list_by_loop(&loop_id).await?;

    // Generate CSV
    let mut wtr = Writer::from_writer(vec![]);
    for task in tasks {
        wtr.write_record(&[
            &task.id,
            &task.title,
            &task.description,
            &task.status,
            &task.priority.to_string(),
        ])?;
    }

    let csv_bytes = wtr.into_inner()?;
    Ok(Response::builder()
        .header("Content-Type", "text/csv")
        .header("Content-Disposition", "attachment; filename=tasks.csv")
        .body(csv_bytes))
}

pub async fn import_tasks(
    State(repo): State<Arc<TaskRepository>>,
    Auth(user_id): AuthExtractor,
    Path(loop_id): Path<String>,
    mut multipart: Multipart,
) -> Result<Json<ImportResult>> {
    // Parse CSV file
    let file_field = multipart.next_field().await?
        .ok_or_else(|| anyhow!("No file uploaded"))?;

    let filename = file_field.file_name().unwrap_or("tasks.csv");
    let data = file_field.bytes().await?;

    let mut rdr = Reader::from_reader(data.as_ref());
    let mut imported = 0;

    for result in rdr.deserialize() {
        let record: CsvTaskRecord = result?;
        let create_task = CreateTask {
            loop_id: loop_id.clone(),
            title: record.title,
            description: record.description,
            priority: record.priority,
            parent_task_id: None,
            created_by: user_id.clone(),
        };

        repo.create(create_task).await?;
        imported += 1;
    }

    Ok(Json(ImportResult { count: imported }))
}
```

- **OAuth State Validation:** CSRF-resistant OAuth flow
- **Input Validation:** All user inputs validated and sanitized
- **SQL Injection Prevention:** Use SQLx type-safe queries only
- **XSS Prevention:** HTML templates escape user content
- **Rate Limiting:** 60 requests/minute per IP
- **Session Security:** Secure session cookies (HttpOnly, Secure, SameSite)
